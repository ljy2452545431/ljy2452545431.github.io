<h2><a id="webpack_3"></a>什么是webpack</h2> 
<p>webpack可以看作是打包模块化 javascript 的工具，在webpack 里一切文件皆模块，通过 loader 转换文件，通过 plugin 注入钩子，最后输出由多个模块组合成的文件，webpack 专注构建模块化项目；</p> 
<p><strong>功能：</strong> 分析项目结构，找到JavaScript模块以及其它的一些浏览器不能直接运行的拓展语言（Scss，TypeScript等），并将其打包为合适的格式以供浏览器使用。</p> 
<p>要理解webpack，从模块和打包工具两方面来说：</p> 
<h3><a id="_9"></a>什么是模块化</h3> 
<p>相同业务或功能聚集到一起,就是代码一块一块的写 ,一坨代码一个业务或者功能</p> 
<p><strong>代码模块化有什么好处?</strong><br> 可以让工程程序:高内聚,低耦合</p> 
<p><strong>常见的模块化技术:</strong><br> ‘var’、‘module’、‘assign’、‘assign-properties’、‘this’、‘window’、‘self’、‘global’、‘commonjs’、‘system’<br> ‘commonjs2’、‘commonjs-module’、‘commonjs-static’、‘amd’、‘amd-require’、‘umd’、‘umd2’、‘jsonp’</p> 
<h3><a id="_19"></a>什么是打包工具</h3> 
<p>打包工具是一个调度工具，能够组织、并调用基础工具（比如tsc、babel），完成对前端工程的编译。<br> 简单来说就是把多个 js 文件合并成一个 js 文件。<br> <strong>作用：</strong><br> <strong>1.编译代码：</strong> 比如：把新的 js 代码变成老的 js 代码，把 ts 代码变成 js 代码，在 js 文件中，引入其他类型的文件</p> 
<p><strong>2.压缩和&quot;加密&quot;代码</strong><br> 压缩就是：</p> 
<ul><li>把永远不会被运行到的代码删掉</li><li>把变量的名字变短，比如原来你有个变量叫 shaoshiBrother，打包之后就变成了 sb 或 s，也有可能叫 a</li><li>把多余的空格、空行删掉</li></ul> 
<p>&quot;加密&quot;则是：<strong>代码变得更加混乱</strong>，不利于其他公司的人解读。</p> 
<h4><a id="_33"></a>常见的打包工具</h4> 
<h5><a id="grunt__gulp_34"></a>grunt 与 gulp</h5> 
<p>grunt 与 gulp它俩不是打包工具，它们是自动化任务运行器。远古时代没有打包工具时，流行使用它们<br> <strong>Gulp和Grunt的异同点</strong><br> 易于使用：采用代码优于配置策略，Gulp让简单的事情继续简单，复杂的任务变得可管理。<br> 高效：通过利用Node.js强大的流，不需要往磁盘写中间文件，可以更快地完成构建。<br> 高质量：Gulp严格的插件指导方针，确保插件简单并且按你期望的方式工作。<br> 易于学习：通过把API降到最少，你能在很短的时间内学会Gulp。构建工作就像你设想的一样：是一系列流管道。<br> 易用 Gulp相比Grunt更简洁，而且遵循代码优于配置策略，维护Gulp更像是写代码。<br> 高效 Gulp相比Grunt更有设计感，核心设计基于Unix流的概念，通过管道连接，不需要写中间文件。<br> 高质量 Gulp的每个插件只完成一个功能，这也是Unix的设计原则之一，各个功能通过流进行整合并完成复杂的任务。<br> 例如：Grunt的imagemin插件不仅压缩图片，同时还包括缓存功能。<br> 他表示，在Gulp中，缓存是另一个插件，可以被别的插件使用，这样就促进了插件的可重用性。<br> 易学 Gulp的核心API只有5个，掌握了5个API就学会了Gulp，之后便可以通过管道流组合自己想要的任务。</p> 
<h5><a id="snowpack_48"></a>snowpack</h5> 
<p>是一种闪电般快速的前端构建工具，专为现代Web设计，较复杂的打包工具（如Webpack或Parcel）的替代方案，利用JavaScript的本机模块系统，避免不必要的工作并保持流畅的开发体验</p> 
<p>开发阶段，每次保存单个文件时，Webpack和Parcel都需要重新构建和重新打包应用程序的整个bundle。而Snowpack为你的应用程序每个文件构建一次，就可以永久缓存，文件更改时，Snowpack会重新构建该单个文件。</p> 
<h5><a id="parcel_53"></a>parcel</h5> 
<p>是一款完全零配置的前端打包器，它提供了 “傻瓜式” 的使用体验，只需了解简单的命令，就能构建前端应用程序</p> 
<p>Parcel 跟 Webpack 一样都支持以任意类型文件作为打包入口，但建议使用HTML文件作为入口，该HTML文件像平时一样正常编写代码、引用资源。</p> 
<h5><a id="esbuild_58"></a>esbuild</h5> 
<p><em>esbuild</em> 是一个用 go 语言写的 javascript, typescript 打包工具,速度比 webpack 快 100 倍以上。</p> 
<h5><a id="rollup_61"></a>rollup</h5> 
<p>Rollup 是一款 ES Modules 打包器，从作用上来看，Rollup 与 Webpack 非常类似。不过相比于 Webpack，Rollup要小巧的多==&gt; 代码效率更简洁、效率更高,默认支持 Tree-shaking<br> 但缺点也十分明显，加载其他类型的资源文件或者支持导入 CommonJS 模块，又或是编译 ES 新特性，这些额外的需求 Rollup需要使用插件去完成<br> 综合来看，rollup并不适合开发应用使用，因为需要使用第三方模块，而目前第三方模块大多数使用CommonJs方式导出成员，并且rollup不支持HMR，使开发效率降低<br> 但是在用于打包JavaScript 库时，rollup比 webpack 更有优势，因为其打包出来的代码更小、更快，其存在的缺点可以忽略。</p> 
<h5><a id="vite_68"></a>vite</h5> 
<p>vite ，是一种新型前端构建工具，能够显著提升前端开发体验<br> 它主要由两部分组成：<br> 一个开发服务器，它基于 原生 ES 模块 提供了丰富的内建功能，如速度快到惊人的 [模块热更新HMR<br> 一套构建指令，它使用 Rollup打包你的代码，并且它是预配置的，可以输出用于生产环境的优化过的静态资源<br> 其作用类似webpack+ webpack-dev-server，其特点如下：</p> 
<ul><li>快速的冷启动</li><li>即时的模块热更新</li><li>真正的按需编译</li></ul> 
<p>vite会直接启动开发服务器，不需要进行打包操作，也就意味着不需要分析模块的依赖、不需要编译，因此启动速度非常快<br> 利用现代浏览器支持ES Module的特性，当浏览器请求某个模块的时候，再根据需要对模块的内容进行编译，这种方式大大缩短了编译时间</p> 
<h5><a id="webpack_81"></a>webpack</h5> 
<p>是打包工具中最常用的，用户数量最广。<br> 特点：</p> 
<ul><li>虽然臃肿，但不难用</li><li>速度不快，但可接受</li><li><strong>功能多</strong></li><li><strong>bug 少</strong></li><li><strong>非开箱即用,需要自己配置</strong></li></ul>

<h3><a id="loader_245"></a>加载器loader</h3> 
<p>webpack 只能理解 JavaScript 和 JSON 文件，这是 webpack 开箱可用的自带能力。<strong>loader</strong> 让 webpack 能够去处理其他类型的文件，并将它们转换为有效 <a href="https://webpack.docschina.org/concepts/modules" target="_blank" rel="noreferrer noopener">模块</a>，以供应用程序使用，以及被添加到依赖图中。</p> 
<p><strong>loader 用于对模块的源代码进行转换</strong>。loader 可以使你在 <code>import</code> 或&quot;加载&quot;模块时<strong>预处理文件</strong>。因此，loader 类似于其他构建工具中“任务(task)”，并提供了处理前端构建步骤的强大方法。loader 可以将文件从不同的语言（如 TypeScript）转换为 JavaScript，或将内联图像转换为 data URL。<br> 当我们项目中用js引入css 会出现解析打包失败的情况;而 loader 甚至允许你直接在 JavaScript 模块中引入CSS文件！</p> 
<h4><a id="cssloaderstyleloader_251"></a>css-loader&amp;style-loader</h4> 
<p>css-loader解析css文件<br> style-loader把 <code>css-loader</code> 生成的内容，用 <code>style</code> 标签挂载到页面的 <code>head</code> 中</p> 
<h5><a id="1_style__head__254"></a>1.用 <code>style</code> 标签挂载到页面的 <code>head</code> 中</h5> 
<pre><code>module.exports={
//加载器配置loader,
module:{  rules:[  {test:/\.css$/,use:[&quot;style-loader&quot;,&quot;css-loader&quot;]}  //test属性后面为正则表达式， 表示以.css为后缀的文件;  //use里面为使用的什么加载器加载这些文件，use数组执行顺序为从右往左执行；  //只使用一个加载器时可，直接写不用写到数组里  ]  }
}
</code></pre>

</code></pre> 
<h4><a id="babelloader_315"></a>babel-loader</h4> 
<p>Babel 是一个 JavaScript编译器，它是一个工具链，主要的用途就是在旧的浏览器或环境中将ECMAScript 2015+ 代码转换为向后兼容的 js 代码。babel-loader就是用babel工具将ES6转成ES5的一种加载器. 在webpack打包时遇到js文件，就交给babel处理。</p> 
<p>需要下载插件：npm install babel-loader @babel/core @babel/preset-env webpack -D</p> 
<pre><code>//webpack.config.js文件
module: {  rules: [  //exclude:/node_module/ 意思是下载的模块不转码,其他js文件转码  {  test: /\.js$/,  exclude: /(node_modules|bower_components)/,  use: {  loader: &#x27;babel-loader&#x27;,  options: {  presets: [&#x27;@babel/preset-env&#x27;],  //插件的配置  plugins: [&#x27;@babel/plugin-proposal-object-rest-spread&#x27;]  }  }  }  ]
	},
</code></pre> 
<h4><a id="sassloader_340"></a>sass-loader</h4> 
<p>把Sass代码转化为css代码<br> 需要下载插件：npm install sass-loader sass webpack --save-dev</p> 
<pre><code>//webpack.config.js文件:  module: {  rules: [  {  test: /\.s[ac]ss$/i,  use: [  &#x27;style-loader&#x27;,  //不用单独引入 直接运行js代码 动态写入页面  &#x27;css-loader&#x27;,  // 将 Sass 编译成 CSS  &#x27;sass-loader&#x27;,  ],  },  ],  },
</code></pre> 
<h4><a id="_359"></a>加载器总结</h4> 
<ul><li>style-loader: 将css添加到DOM的内联样式标签style里</li><li>css-loader :允许将css文件用js引入，并返回css代码</li><li>less-loader: 处理less</li><li>sass-loader: 处理sass</li><li>eslint-loader: 错误语法检测</li><li>postcss-loader: 用postcss来处理CSS</li><li>autoprefixer-loader: 处理CSS3属性前缀，已被弃用，建议直接使用postcss</li><li>file-loader: 分发文件到output目录并返回相对路径</li><li>url-loader: 和file-loader类似，但是当文件小于设定的limit时可以返回一个Data Url (比如base64编码的图片)</li><li>html-minify-loader: 压缩HTML</li><li>babel-loader :用babel来转换ES6文件到ES5</li><li>ts-loader :用typescript来转换TS文件到JS</li></ul> 
<h3><a id="plugin_374"></a>插件plugin</h3> 
<p>loader 用于转换某些类型的模块，而插件则可以用于执行范围更广的任务。包括：打包优化，资源管理，注入环境变量。</p> 
<p>可以这样理解: loader的关注点在某种类型的文件编码解析上,插件plugin是关注某一个功能点:比如托管服务器,错误语法检测,挂载打包代码到模板文件等等.</p> 
<p>想要使用一个插件，你只需要 <code>require()</code> 它，然后把它添加到 <code>plugins</code> 数组中。多数插件可以通过选项(option)自定义。你也可以在一个配置文件中因为不同目的而多次使用同一个插件，这时需要通过使用 <code>new</code> 操作符来创建一个插件实例。</p> 
<h4><a id="eslintwebpackplugin_380"></a>eslint-webpack-plugin插件</h4> 
<p>它是用来检查语法错误的。<br> 环境准备:<br> <strong>npm install eslint-webpack-plugin --save-dev</strong></p> 
<p>如果未安装 <code>eslint &gt;= 7</code> ，你还需先通过 npm 安装：<br> <strong>npm install eslint --save-dev</strong></p> 
<pre><code>
const ESLintPlugin = require(&#x27;eslint-webpack-plugin&#x27;);

module.exports = {  // ...  plugins: [new ESLintPlugin(options)],  // ...
};

//options的参数配置:
context:__dirname+&quot;/src&quot; //指定文件根目录
extensions:String|Array[String] //指定需要检查的扩展名.不配置默认为&quot;js&quot;
exclude:&quot;node_modules&quot; //指定需要排除的文件及目录。必须是相对于 options.context 的相对路径。
files:String|Array[String] //指定目录、文件或 globs ，必须是相对于 options.context 的相对路径。 如果是目录则递归查找所有匹配 options.extensions 选项的文件。 
</code></pre>

<pre><code>const HtmlWebpackPlugin = require(&#x27;html-webpack-plugin&#x27;);
