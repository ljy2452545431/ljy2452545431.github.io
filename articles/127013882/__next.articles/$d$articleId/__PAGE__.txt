<h2><a id="_3"></a>公共数据配置</h2> 
<p>因为v2使用公共配置时一般绑定在原型上无论是否使用都在每一个组件的this链上,这样的设计不太友好,v3提供了专门公共数据配置的方式: globalProperties getCurrentInstance</p> 
<p>globalProperties：添加可以在应用程序内的任何组件实例中访问的全局 property。属性名冲突时，组件的 property 将具有优先权。<br> getCurrentInstance：返回当前组件的实例对象，也就是当前vue这个实例对象</p> 
<pre><code>//再main.js中
const app=createApp(App)
app.config.globalProperties.$common=公共数据
//组件中钩子中:
//getCurrentInstance()获取当前组件实例对象
//当前组件的实例对象解构的proxy对象中就有$common
//注意点是这个函数要在组件钩子中使用,不要在普通函数中使用
</code></pre> 
<pre><code>&lt;script setup&gt;
 import { getCurrentInstance } from &quot;vue&quot;;
 const {proxy}= getCurrentInstance()  //解构组件的实例对象的proxy对象,里面就有$common
 let common=proxy.$common  //接受公共数据
 &lt;/script&gt;
</code></pre>

<h2><a id="_70"></a>插件配置</h2> 
<p>同2.0一样use函数接受一个函数或者对象(对象有install函数) 然后会调用这个传入的回调函数 给它传参app对象,以此来实现第三方插件</p> 
<p>以axios为例：</p> 
<pre><code>//main.js文件
import { createApp } from &#x27;vue&#x27;
import App from &#x27;./App.vue&#x27;
import $axios from &quot;./http/$axios.js&quot;
import router from &#x27;./router/router.js&#x27;
createApp(App).use(router).use($axios).mount(&#x27;#app&#x27;)

//外部专门放插件的js文件中
import axios from &quot;axios&quot;
function $axios(app){
	axios.defaults.baseURL=&quot;http://127.0.0.1:5173/api&quot;
	app.config.globalProperties.$axios=axios
}
export default $axios;
</code></pre> 
<p>使用方法同上，这样写的好处利于我们对插件的统一管理和维护</p>

<h2><a id="_177"></a>数据仓库配置</h2> 
<p>vuex<br> vuex3.0适用于vue2.0<br> vuex4.0适用于vue3.0和2.0<br> 这里主要介绍一款超前的数据仓库Pinia</p> 
<p>Pinia从使用角度和之前的Vuex一样。<br> Store是保存状态与业务逻辑的实体，有三个核心概念。</p> 
<ul><li>state：存储全局状态</li><li>getters：类似于组件的computed，根据已有state封装派生数据，也具有缓存的特性</li><li>actions：类似于组件的methods,用来封装业务逻辑，支持同步和异步</li></ul> 
<p>Pinia 适用于3.0 为了兼容2.0也能使用 主要是给3.0的组合式API设计的</p> 
<p>1.安装</p> 
<pre><code>npm install pinia
</code></pre> 
<p>2.写一个store文件</p> 
<p>使用defineStore定义容器<br> 参数1：是对仓库的命名，名称必须具备唯一性；<br> 参数2：配置的选项对象，即state、getters、actions，其中state的写法必须是函数，为了避免在服务端交叉请求导致的状态数据污染，而且必须是箭头函数，为了更好的TS类型推导。</p> 
<pre><code>//  store/index.js文件
import { defineStore } from &#x27;pinia&#x27;
//这里官网是单独导出  是可以写成默认导出的  官方的解释为大家一起约定仓库用use打头的单词 固定统一小仓库的名字不易混乱
export const useStore = defineStore(&#x27;storeId&#x27;, {  // 这里易错语法:如果箭头函数直接指向返回值  记得把返回的对象用小括号括起来  state: () =&gt; {  return {  name: &#x27;ljy&#x27;,  count:0  }  }
})

//main.js文件
import { createPinia } from &#x27;pinia&#x27;
let app=createApp(App)
app.use(createPinia())
</code></pre> 
<p>3.组件中的使用</p> 
<pre><code>&lt;script setup&gt;
	import {useStore} from &quot;../store/index.js&quot;  //引入仓库
	let store=useStore()  console.log(store,msg,111)	
&lt;/script&gt;
</code></pre> 
<p>4.修改数据</p> 
<pre><code>//修改仓库状态1:
&lt;script setup&gt;
	import useStore from &quot;../../store/index.js&quot;
	let store=useStore()  let fm=()=&gt;{store.name=&quot;修改成功&quot;}//store是一个响应性对象 因此可以修改并刷新
	let {name}=store
	let fn=()=&gt;{ name=&quot;修改失败&quot;} //解构之后修改是不行的,因为解构后name为非响应式变量  //解决方案:利用toRefs把响应式对象的属性解构为响应性的变量  import {toRefs} from &quot;vue&quot;  import useStore from &quot;../../store/index.js&quot;
	let store=useStore()
	let {name}=toRefs(store)
	let fn=()=&gt;{msg.value=&quot;修改成功&quot;}  //一定不要忘了value
&lt;/script&gt;

//修改仓库状态2:
store.$reset()//将状态 重置 到其初始值

//修改仓库状态3:
store.$patch({  name:&quot;修改成功&quot;,  count:store.count++,
})
store.$patch((state)=&gt;{  state.name=&quot;666修改成功&quot;;  state.count++,
})

//$patch整体修改个单条修改的区别?
store.name=&quot;修改成功&quot;
store.count++
//状态刷新一次,可以批量修改
</code></pre> 
<p>5.订阅修改</p> 
<pre><code>//可以通过 store 的 $subscribe() 方法查看状态及其变化,通过patch修改状态时就会触发一次
store.$subscribe((mutation, state) =&gt; {  // 每当它发生变化时，将整个状态持久化到本地存储  localStorage.setItem(&#x27;test&#x27;, JSON.stringify(state))
})
</code></pre> 
<p>案例：</p> 
<pre><code>//store仓库文件中
import { defineStore } from &#x27;pinia&#x27;
export const useStore = defineStore(&#x27;storeId&#x27;, {
state: () =&gt; {
return {
name: &#x27;ljy&#x27;,
count:22,
shuju:JSON.parse(window.localStorage.getItem(&#x27;test&#x27;)),  //读取缓存中的数据
}
}
})  //组件中
&lt;script setup&gt;
 import {reactive} from &#x27;vue&#x27;
 import { useStore } from &quot;../../store/index.js&quot;
 let store= useStore()
 let shuju= reactive({})
 let fn=()=&gt;{  store.$patch((state)=&gt;{  state.count++  state.name=&quot;ljy666&quot;  })
 }
 store.$subscribe((mutation, state) =&gt; {  window.localStorage.setItem(&#x27;test&#x27;, JSON.stringify({name:store.name, count:store.count}))  //设置缓存，保存上一次最后修改的值  shuju.name= store.shuju.name  shuju.count = store.shuju.count  })
&lt;/script&gt;
&lt;template&gt;
&lt;button @click=&quot;fn&quot;&gt;点击修改仓库&lt;/button&gt;
&lt;h1&gt;{{store.name}}---{{store.count}}&lt;/h1&gt;
&lt;h2&gt;每次更新的数据： &lt;span v-for=&quot;(item, index) in shuju&quot; :key=&quot;index&quot;&gt;{{item}}&lt;/span&gt;&lt;/h2&gt;
&lt;/template&gt;
</code></pre>

<p>6.Getter</p> 
<p>Getter 完全等同于 Store 状态的 <a href="https://v3.vuejs.org/guide/reactivity-computed-watchers.html#computed-values" target="_blank" rel="noreferrer noopener">计算值</a>。 它们可以用 <code>defineStore()</code> 中的 <code>getters</code> 属性定义。 他们接收“状态”作为第一个参数<strong>以鼓励</strong>箭头函数的使用：(ps:虽然鼓励但是依然提供了非es6玩家的使用方式 内部可以用this代表state)</p> 
<pre><code>//store仓库
import { defineStore } from &#x27;pinia&#x27;
export const useStore = defineStore(&#x27;storeId&#x27;, {
state: () =&gt; {
return {
name: &#x27;ljy&#x27;,
count:22,
shuju:JSON.parse(window.localStorage.getItem(&#x27;test&#x27;)),
}},
getters: {
Count: (state) =&gt; state.count * 2,
},
})

//组件中直接使用:&lt;h1&gt;{{store.Count}}&lt;/h1&gt;
</code></pre> 
<p>7.Actions<br> 在pinia中没有提供mutaion 因为Actions就够了(它可以异步同步的统一修改状态)<br> 之所以提供这个功能 就是为了项目中的公共修改状态的业务统一<br> 注：定义actions时不要使用箭头函数，因为箭头函数绑定外部this。使用容器中的state 时，action通过this操作。</p> 
<p>8.模块化<br> 一个文件一个小仓库,仓库之间可以相互访问数据 不同组件也可以访问任意小仓库数据</p> 
<pre><code>//store/car.js文件
export const car = defineStore(&#x27;car&#x27;, {  state: () =&gt; ({  counter: 0,  }),  actions: {  }
})

//store/userinfo.js文件
export const userinfo = defineStore(&#x27;userinfo&#x27;, {  state: () =&gt; ({  counter: 0,  }),  actions: {  fn(state){state.counter=100}  }
})  //A组件可以用car,userinfo两个仓库的数据
import {car} from &quot;@/store/car.js&quot;
import {userinfo} from &quot;@/store/userinfo.js&quot;
let store1=car()
store1.counter
let store2=userinfo()
store2.counter

//car仓库使用userinfo仓库跟组件一样的使用方式
import {userinfo} from &quot;@/store/userinfo.js&quot;
let store2=userinfo()
store2.counter
store2.fn()
