<h2><a id="vuex_4"></a>什么是vuex</h2> 
<p>Vuex是一个状态管理工具，采用集中式存储管理应用的所有组件的状态，并且以相应的规则保证状态可预测的方式发生改变。本质就是把组件的共享状态和触发修改状态的函数抽离出来，这样就能获得状态或者触发行为。</p> 
<h2><a id="Vuex_7"></a>Vuex的特点</h2> 
<p>1.能够在vuex中集中管理共享的数据，易于开发和后期维护</p> 
<p>2.能够高效地实现组件之间的数据共享, 提高开发效率</p> 
<p>3.存储在 vuex中的数据都是响应式的，能够实时保持数据与页面的同步</p> 
<p>4.一般情况下，只有组件之间共享的数据，才有必要存储到vuex中;</p> 
<p>5.对于组件中的私有数据，依旧存储在组件自身的data中即可.</p> 
<h2><a id="Vuex_18"></a>什么情形下适合使用Vuex？</h2> 
<p>如果不打算开发大型单页应用，使用Vuex就会变得很冗余，就会有“牛刀杀鸡”的感觉，因为它会附带很多概念。这种情况下使用store模式就足够了。</p> 
<p>如果正在开发一个中大型的单页应用，Vuex是更好的选择。</p>

<h2><a id="Mutation_96"></a>Mutation</h2> 
<p>组件中希望更改 Vuex 的 store 中的状态(数据)的唯一方法是提交 mutation<br> 不要用赋值表达式直接在组件中给store设置新数据<br> 这样设计的原因是,只有通过mutation来更新数据,它才会去帮我们通知所有使用数据的组件更新数据 刷新UI</p> 
<p>注意:一条重要的原则就是要记住 mutation 必须是同步处理<br> <strong>为什么必须是同步处理？</strong><br> 因为每一条mutation都会被devtools记录，devtools需要捕捉前一状态、后一状态。如果mutation函数中如果有异步函数，devtools无法得知异步函数什么时候执行，也就无法记录状态的变更。</p> 
<p>设计：</p> 
<pre><code>mutations: {  mychange(state,obj){  方式一：state.arr[0].price=obj  方式二：state.arr[0].price=obj.n  }  },
</code></pre> 
<p>使用：</p> 
<pre><code>//直接触发并传值(提交载荷)
方式一：this.$store.commit(&quot;mychange&quot;,10)  //可以以一个对象的形式传入
方式二：this.$store.commit(&quot;mychange&quot;,{n:10})  方式二另一种写法：this.$store.commit({type:&quot;mychange&quot;,n:10})  //type属性值是需要触发的事件名,n则为obj下面的键值对
</code></pre> 
<p>案例：</p> 
<pre><code>//vuex文件中
export default new Vuex.Store({  state: {  msg:&quot;所有组件共享的数据&quot;,  arr:[{id:1,price:1,count:22},{id:2,price:2,count:25},{id:3,price:1,count:26}]  },  getters: {  //当作计数属性使用  mycomput(state){  //计算总价  return state.arr.reduce((n1,n2)=&gt;{return n1+n2.price*n2.count},0)  }  },  //更改状态  mutations: {  mychange(state,obj){  state.arr[0].price=obj  }  },  })

<h2><a id="Action_192"></a>Action</h2> 
<p>actions选项的功能和mutations选项类似，但是也有不同之处：<br> Actions提交的是mutation，而不是直接变更状态；<br> Actions里面可以包含任意的异步操作；</p> 
<p>所有的Action函数都接受一个与store实例具有相同方法和属性的context对象，这里的context对象指向当前的仓库，也就是store。因此在函数体中可以调用context.commit提交触发状态，相当于store.commit。这里注意，context对象不是store对象本身，这里相当于复制体。</p> 
<p>设计：</p> 
<pre><code>  actions: {  mychange2(ctx,obj){  setTimeout(()=&gt;{  //提交载荷  ctx.commit(&quot;mychange&quot;,obj)  },1000)  }  },
</code></pre> 
<p>使用：</p> 
<pre><code>//直接分发
this.$store.dispatch(&quot;mychange2&quot;, 20)
//以对象形式
this.$store.dispatch(&#x27;mychange2&#x27;,{n:20})
this.$store.dispatch({type: &#x27;mychange2&#x27;,n:20})
</code></pre> 
<h2><a id="Module_219"></a>Module</h2> 
<p>可用于业务分块开发:<br> 由于使用单一状态树，应用的所有状态会集中到一个比较大的对象。当应用变得非常复杂时，store 对象就有可能变得相当臃肿。<br> 为了解决以上问题，Vuex 允许我们将 store 分割成模块（module）。每个模块拥有自己的 state、mutation、action、getter</p> 
<pre><code>//分块设计:
const moduleA = {  namespaced: true,//局部命名空间(让state的中变量与其他模块中的同名变量不冲突)  state: { msg:1 },  mutations: { change(state,n){state.msg=n} },  actions: { change(context,n){context.commit(&quot;change&quot;,n)} },  getters: { x(state){return state.msg} }
}

const moduleB = {  namespaced: true,//局部命名空间  state: {  msg:1 },  mutations: { change(state,n){state.msg=n} },  actions: { change(context,n){context.commit(&quot;change&quot;,n)} },  getters: { x(state){return state.msg} }
}

const store = new Vuex.Store({  modules: {  a: moduleA,  b: moduleB  }
})

//组件中的使用:
this.$store.state.a.msg // -&gt; moduleA 的状态
this.$store.state.b.msg // -&gt; moduleB 的状态
this.$store.commit(&quot;a/change&quot;,100)-&gt; moduleA 的mutations
this.$store.commit(&quot;b/change&quot;,200)-&gt; moduleB 的mutations
this.$store.getters[&quot;a/x&quot;]-&gt; moduleA 的getters
this.$store.getters[&quot;b/x&quot;]-&gt; moduleB 的getters
this.$store.dispatch(&quot;a/change&quot;,100)-&gt; moduleA 的actions
this.$store.dispatch(&quot;b/change&quot;,200)-&gt; moduleB 的actions
</code></pre>
