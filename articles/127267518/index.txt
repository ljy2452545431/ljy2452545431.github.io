<h2><a id="react_3"></a>react特点</h2> 
<h3><a id="_4"></a>优势</h3> 
<ul><li> <p><strong>声明式设计</strong> −React采用声明范式，可以轻松描述应用。</p> <pre><code class="prism language-react">//命令式编程：命令“机器”如何去做事情(how)，这样不管你想要的是什么(what)，它都会按照你的命令实现。类似jquery 操作DOM,创建一个页面，一点点的告诉DOM 怎么去挂载，你要怎么去做；JQ\原生 都是命令式编程，都是在做DOM 操作。

//声明式编程：告诉“机器”你想要的是什么(what)，让机器想出如何去做(how)。
</code></pre> </li><li> <p><strong>高效</strong> −React通过对DOM的模拟，最大限度地减少与DOM的交互。</p> <pre><code class="prism language-react">  //1.虚拟DOM（Virtual  DOM）  用js 对象来模拟页面上的DOM 和DOM嵌套**实现DOM 元素的高效更新  //2.Diff 算法  tree diff  component diff  element diff
</code></pre> <p>​</p> </li><li> <p><strong>灵活</strong> −React可以与已知的库或框架很好地配合。</p> </li><li> <p><strong>JSX</strong> − JSX 是 JavaScript 语法的扩展。React 开发不一定使用 JSX ，但我们建议使用它。</p> </li><li> <p><strong>组件</strong> − 通过 React 构建组件，使得代码更加容易得到复用，能够很好的应用在大项目的开发中。模块化</p> <p>vue的组件是通过.vue 文件（template/script/style）实现的</p> <p>react中没有像vue中那样的模板文件，在react里一切都是以js来实现的</p> </li><li> <p><strong>单向响应的数据流</strong> − React 实现了单向响应的数据流，从而减少了重复代码，这也是它为什么比传统数据绑定更简单。</p> </li></ul> 
<h3><a id="_40"></a>劣势</h3> 
<ul><li>学习成本很高，学习曲线很陡</li><li>react本身能做的事并不多，想做大东西必须得用react插件（全家桶）</li></ul> 
<h2><a id="jsx_46"></a>jsx</h2> 
<h3><a id="_47"></a>介绍</h3> 
<p>全称: <strong>JavaScript XML</strong>， React 使用 JSX 来替代常规的 JavaScript。</p> 
<p>JSX 是一个看起来很像 XML 的 JavaScript 语法扩展。</p> 
<p>我们不需要一定使用 JSX，但它有以下优点：</p> 
<ul><li> <p>JSX 执行更快，因为它在编译为 JavaScript 代码后进行了优化。</p> </li><li> <p>它是类型安全的，在编译过程中就能发现错误。</p> </li><li> <p>使用 JSX 编写模板更加简单快速。</p> </li><li> <p>作用: 用来创建react虚拟DOM(元素)对象</p>  <ul><li>var ele = &lt;h1&gt;Hello JSX!&lt;/h1&gt;;</li><li>注意1: 它不是字符串, 也不是HTML/XML标签</li><li>注意2: 它最终产生的就是一个JS对象</li></ul> </li><li> <p>标签名任意: HTML标签或其它标签</p> </li><li> <p>标签属性任意: HTML标签属性或其它</p> </li><li> <p>基本语法规则</p>  <ul><li>遇到 &lt;开头的代码, 以标签的语法解析: html同名标签转换为html同名元素, 其它标签需要特别解析</li><li>遇到以 { 开头的代码，以JS的语法解析: 标签中的js代码必须用{ }包含</li></ul> </li><li> <p>babel.js的作用</p>  <ul><li>浏览器的js引擎是不能直接解析JSX语法代码的, 需要babel转译为纯JS的代码才能运行</li><li>只要用了JSX，都要加上type=“text/babel”, 声明需要babel来处理</li></ul> </li></ul>

<h2><a id="_167"></a>组件</h2> 
<p>React.js 中一切皆组件，用 React.js 写的其实就是 React.js 组件。</p> 
<p>我们在编写 React.js 组件的时候，一般都需要继承 React.js 的 <strong>Component</strong>（类定义）。一个组件类必须要实现一个 <strong>render 方法</strong>，这个 <strong>render 方法必须要返回一个 JSX 元素</strong>。但这里要注意的是，必须要用一个外层的 JSX 元素把所有内容包裹起来。返回并列多个 JSX 元素是不合法的。</p> 
<h3><a id="_172"></a>定义单个组件</h3> 
<p>方式1：通过React自定义组件（DOM元素）：<strong>类定义</strong></p> 
<pre><code>import React, { Component } from &#x27;react&#x27;

export default class Box4 extends Component {  render() {  return (  &lt;div&gt;Box4&lt;/div&gt;  )  }
}
</code></pre> 
<p>方式2：通过React自定义组件（DOM元素）：<strong>函数定义</strong></p> 
<pre><code>import React from &#x27;react&#x27;

export default function Box4(props) {  return (  &lt;div&gt;Box4&lt;/div&gt;  )
}

</code></pre> 
<p>方式3：<strong>不建议使用</strong>，React.createClass创建组件的方式在react 16版本中去除。</p> 
<pre><code>var MyApp = React.createClass({  render: function() {  return &lt;h1&gt;Hello World！&lt;/h1&gt;;  }
});
</code></pre> 
<h3><a id="_204"></a>使用组件</h3> 
<pre><code>import React from &#x27;react&#x27;;
import ReactDOM from &#x27;react-dom/client&#x27;;
import Box4 from &#x27;./Box4.jsx&#x27;;  导入自定义组件
const root = ReactDOM.createRoot(document.getElementById(&#x27;root&#x27;));  //关联页面根元素
root.render(&lt;Box4 /&gt;);  //给根元素内部渲染组件模板
</code></pre>

<h2><a id="State_324"></a>State</h2> 
<p>React 的核心思想是组件化的思想，应用由组件搭建而成，而组件中最重要的概念是State（状态），State是一个组件的UI数据模型，是组件渲染时的数据依据。</p> 
<h3><a id="State_327"></a>如何定义State</h3> 
<p>组件中用到的一个变量是不是应该作为组件State，可以通过下面的4条依据进行判断：</p> 
<ol><li>这个变量是否是通过Props从父组件中获取？如果是，那么它不是一个状态。</li><li>这个变量是否在组件的整个生命周期中都保持不变？如果是，那么它不是一个状态。</li><li>这个变量是否可以通过其他状态（State）或者属性(Props)计算得到？如果是，那么它不是一个状态。</li><li>这个变量是否在组件的render方法中使用？如果<strong>不是</strong>，那么它不是一个状态。这种情况下，这个变量更适合定义为组件的一个普通属性。</li></ol> 
<p>注意：并不是组件中用到的所有变量都是组件的状态！</p> 
<pre><code>import Box5 from &#x27;./Box5&#x27;
import React, { Component } from &#x27;react&#x27;
export default class Box4 extends Component {  constructor(arg){  super(arg)  this.state={  msg:0  }  //写法一  this.change1=()=&gt;{  this.setState({msg:this.state.msg+1})  //使用setState函数更改状态  }  //写法二  this.change2=()=&gt;{  this.state.msg++  this.setState(this.state)  //修改变量之后，调用setState刷新render  从而页面重新取到已经修改后的值  }  }  render() {  return (  &lt;div&gt;  &lt;h1&gt;Box4组件中&lt;/h1&gt;  &lt;h2&gt;{this.state.msg}&lt;/h2&gt;  &lt;button onClick={this.change1}&gt;change1&lt;/button&gt;&lt;button onClick={this.change2}&gt;change2&lt;/button&gt;  &lt;/div&gt;  )  }
}

</code></pre> 
<p>注意：<strong>React在ES6的实现中，规定state在constructor中实现</strong></p> 
<p><em><strong>正确定义State</strong></em>的方式如下：</p> 
<p>（1）在constructor中实现state</p> 
<p>（2）在constructor中通过bind绑定事件函数（事件函数是用来改变状态）</p> 
<p>（3）在事件函数内部使用setState函数更改状态</p> 
<p>（4）在组件中的render函数中使用该状态</p> 
<p>（5）在组件上需要设置监听事件，去触发事件函数的执行</p> 
<h3><a id="setState_381"></a>setState设置状态</h3> 
<p>（1）语法：</p> 
<p><strong>setState(object nextState[, function callback])</strong></p> 
<p>（2）说明：</p> 
<ul><li>setState是React事件处理函数中和回调函数中触发UI更新的主要方法。</li><li>不能在组件内部通过this.state修改状态，因为该状态会在调用setState()后被替换。</li><li>setState()不一定是同步的，为了性能提升，React会批量执行state和DOM渲染。</li><li>setState()总是会触发一次组件重绘，但可在shouldComponentUpdate()中实现一些条件渲染逻辑来解决。</li></ul> 
<p>同步设置多个状态时(不常用)，可以在setState函数的<strong>第二个参数可以传递一个function回调函数</strong>，如下：</p> 
<pre><code>this.change1=()=&gt;{  this.setState({msg:this.state.msg+1},()=&gt;{  this.state.num+= this.state.msg  })  }
</code></pre> 
<p>**状态上移：**当存在多个组件共同依赖一个状态，或是当子组件的props 数据需要被修改时，将这个状态放到对应组件的父组件中：</p> 
<h3><a id="State__Props__405"></a>State 与 Props 区别</h3> 
<p>除了State, 组件的Props也是和组件的UI有关的。他们之间的主要区别是：</p> 
<ul><li>props 中的数据都是外界传递过来的</li><li>state 中的数据都是组件私有的；（通过Ajax 获取回来的数据，一般都是私有数据）</li><li>props 中的数据都是只读的，不能重新赋值</li><li>state 中的数据都是可读可写的</li><li>State定义在constructor内部，在super(props)代码后面；Props默认值定义在类（组件）的外部</li></ul> 
<p>当子组件的属性值是可变值时，采用状态上移：</p> 
<p><strong>状态上移</strong>通过属性将父组件的状态传递到子组件，那么父组件的状态发生变化时，子组件的属性也会改变</p> 
<h3><a id="stateprops__421"></a>state/props 实现父子组件通信</h3> 
<ul><li>子组件获取父组件整个组件进行传参  <ul><li>父组件在调用子组件时，传入一整个组件给子组件**&lt;Children parent={ this } /&gt;**</li><li>父组件中定义一个方法getChildrenMsg(resulet, msg)，用来获取子组件传来的值以及执行其他操作</li><li>子组件在通过this.props来获取到一整个组件this.props.parent 或者this.props[parent]</li><li>子组件调用父组件步骤2里定义的方法进行传值this.props.parent.getChildrenMsg(this,val)</li></ul> </li></ul> 
<p>Parent:</p> 
<pre><code>import Box5 from &#x27;./Box5&#x27;
import React, { Component } from &#x27;react&#x27;
export default class Box4 extends Component {  constructor(arg){  super(arg)  this.state={  msg:0,  num:0  }  //写法一  this.change1=()=&gt;{  this.setState({msg:this.state.msg+1},()=&gt;{  this.state.num+= this.state.msg  })  }  //写法二  this.change2=()=&gt;{  this.state.msg++  this.setState(this.state)  }  this.change3=(arg,arg2)=&gt;{  this.state.msg=arg  this.state.num=arg2  this.setState(this.state)  }  }  render() {  let props={  msg:this.state.msg,  num:this.state.num,  change3:this.change3  }  return (  &lt;div&gt;  &lt;h1&gt;Box4组件中&lt;/h1&gt;  &lt;h2&gt;msg--{this.state.msg}&lt;/h2&gt;  &lt;h2&gt;num--{this.state.num}&lt;/h2&gt;  &lt;Box5 {...props}&gt;&lt;/Box5&gt;  &lt;button onClick={this.change1}&gt;change1&lt;/button&gt;&lt;button onClick={this.change2}&gt;change2&lt;/button&gt;  &lt;/div&gt;  )  }
}
Children:

<h2><a id="Redux_493"></a>Redux</h2> 
<p>我们为什么需要状态管理器Redux？为了方便的组织和管理组件之间的数据。</p> 
<p>Redux是什么？<br> Redux是一个流行的JavaScript框架，为应用程序提供一个可预测的状态容器。Redux基于简化版本的Flux框架，Flux是Facebook开发的一个框架。在标准的MVC框架中，数据可以在UI组件和存储之间双向流动，而Redux严格限制了数据只能在一个方向上流动。</p> 
<p><img src="https://i-blog.csdnimg.cn/blog_migrate/58baa99db0f15ccb2be353b5f8641ff8.png" alt="请添加图片描述" loading="lazy" decoding="async"><br> Store：存储数据的公告区域；eg–图书管理员；</p> 
<p>React Component：页面组件；eg–借书的用户；</p> 
<p>Reducer：数据存放位置；eg–图书记录本；</p> 
<p>Action Creators：动作；eg–结束的时候，跟图书管理员说的话；</p> 
<ul><li> <p>Redux基本原则</p>  <ul><li>单一数据源；</li><li>state是只读的；</li><li>使用纯函数来执行修改；</li></ul> </li><li> <p>Redux核心API</p>  <ul><li>createStore(reducer)：创建数据仓库: import {createStore} from “redux”；</li><li>store.getState()：用于获取store里面的数据；</li><li>store.dispatch(action)：用于派发action，触发reducer,执行修改动作；</li><li>store.subscribe(componentMethods)：订阅store的修改，只要store发生改变，组件中的回调函数就会被执行；</li></ul> </li></ul>
