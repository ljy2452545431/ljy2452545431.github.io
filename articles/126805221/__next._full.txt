<h2><a id="_5"></a>路由是什么</h2> 
<p>后端路由:对于前端的网络请求,不同的pathname,去执行后端的不同业务<br> 前端路由:不同的网址对应各自的页面<br> vue的前端路由:SPA应用要做出路由效果,就得判断当前网址,然后切换组件<br> vue-router就是专门做切换组件的功能,它是一个单独的技术,依赖vue<br> 就像jQuery和dom操作一样</p> 
<h2><a id="_12"></a>如何引入路由</h2> 
<p>方法一：通过CDN引入 (基本不用)</p> 
<pre><code>&lt;script src=&quot;https://lf3-cdn-tos.bytecdntp.com/cdn/expire-1-M/vue-router/4.0.13/vue-router.cjs.min.js&quot; type=&quot;application/javascript&quot;&gt;&lt;/script&gt;
</code></pre> 
<p>方法二：npm下载引入使用</p> 
<pre><code>npm i vue-router --save-dev//注意:这种下载不好,因为打包之后容易出问题
 npm i vue-router --save或者 npm i vue-router --S  在main.js入口文件中引入

<h2><a id="query_108"></a>query传参和动态路由传参</h2> 
<p><strong>query传参：</strong><br> 第一种：使用router-link跳转传参</p> 
<pre><code>//直接拼接到网址后面用?隔开
&lt;router-link to=&quot;/login?name=ljy&amp;pwd=123456&quot;&gt;点击跳转&lt;/router-link&gt;
//以网址对象形式传参
&lt;router-link :to=&quot;{path:&#x27;/login&#x27;,query:{name:&#x27;ljy&#x27;,pwd:&#x27;123456&#x27;}}&quot;&gt;点击跳转&lt;/router-link&gt;
</code></pre> 
<p>第二种：编程式导航跳转传参</p> 
<pre><code>this.$router.push(&quot;/login?name=ljy&amp;pwd=123456&quot;)
this.$router.push({path:&#x27;/login&#x27;,query:{name:&#x27;ljy&#x27;,pwd:&#x27;123456&#x27;}})
</code></pre> 
<p>两者都用：this.$route.query 接受获取数据,如果没有传参 这个值就没有<br> 接受获取数据可以写再目标页面的created生命周期函数之后的所有地方</p> 
<p><strong>动态路由传参</strong><br> 第一种：使用router-link跳转传参</p> 
<pre><code>&lt;router-link to=&quot;/login/参数&quot;&gt;点击跳转&lt;/router-link&gt;
&lt;router-link :to=&quot;{name:&quot;login&quot;,params:{id:参数}}&quot;&gt;点击跳转&lt;/router-link&gt;
</code></pre> 
<p>第二种：编程式导航跳转传参</p> 
<pre><code>this.$router.push(&quot;/login/参数&quot;)
this.$router.push({name:&quot;login&quot;,params:{id:参数}})//必须用name跳路由 name就是注册路由时的name
</code></pre> 
<p><strong>小结：</strong><br> query传参是吧参数放在querystring字段中<br> 动态路由传参就是把参数放在pathname中</p> 
<p><strong>query 传参和 params 传参的区别</strong><br> 用法上的： query 要用 path 来引入，params 要用 name 来引入，接收参数都是类似的，分别是 this.$route.query.name 和 this.$route.params.name。注意接收参数的时候，已经是$route 而不是$router 了哦！！<br> 展示上的： query 更加类似于我们 ajax 中 get 传参，params 则类似于 post，说的再简单一点，前者在浏览器地址栏中显示参数，后者则不显示所以两者不能同时使用</p> 
<h2><a id="_144"></a>路由嵌套</h2> 
<p>嵌套路由又称为子路由，在实际应用中，通常由多层嵌套的组件组合而成。同样地，URL中各段动态路景观也按某种结构对应嵌套的各层组件</p> 
<p>配置嵌套路由</p> 
<pre><code>const routes = [
{
path: &#x27;/home&#x27;,
name:&#x27;home&#x27;,
component: () =&gt; import(&#x27;../views/home/index.vue&#x27;),
redirect:&quot;/home/box1&quot;,  //重定向，输入home自动进入box1界面
children:[{  //注册子组件  path:&#x27;box1&#x27;,  name:&#x27;box1&#x27;,  component:()=&gt;import(&#x27;../views/home/views/box1.vue&#x27;)
},{  path:&#x27;box2&#x27;,  //path表示相对地址 ；也可以这么写/home/box2  name:&#x27;box2&#x27;,  component:()=&gt;import(&#x27;../views/home/views/box2.vue&#x27;)
}]}]
</code></pre> 
<p>再父组件中添加&lt;router-view&gt;&lt;/router-view&gt;</p> 
<pre><code>&lt;div id=&quot;&quot;&gt;  &lt;h1&gt;home界面&lt;/h1&gt;  &lt;router-view&gt;&lt;/router-view&gt;
	&lt;/div&gt;
</code></pre> 
<p><img src="https://i-blog.csdnimg.cn/blog_migrate/92d1713f716ad2d6fe494d3a3b9e5558.gif" alt="请添加图片描述" loading="lazy" decoding="async"></p> 
<p><strong>小结：</strong><br> 1.*代表所有匹配都通过<br> 2. redirect代表重定向<br> 3. 语法:一个路由对象的设计中包含: path(路由匹配的路径) component(匹配路径时对应渲染的组件) redirect(匹配路径时重新匹配另外的路径) children(子路由们的数组) name(路由的名字,方便直接通过名字来匹配路由)</p> 
<h2><a id="routerroutesroute_179"></a>router、routes、route的区别</h2> 
<p>1.router：路由器对象（new的路由器对象），包含一些操作路由的功能函数，来实现编程式导航。一般指的是在任何组件内访问路由。如：路由编程式导航的$router.push()</p> 
<p>2.routes：指创建vue-router路由实例的配置项。用来配置多个route路由对象</p> 
<p>3.route：指路由对象表示当前激活的路由的状态信息。如：this.$route指的是当前路由对象，path/meta/query/params</p> 
<h2><a id="_186"></a>跳转路由的其它方式</h2> 
<p>1.this.$router.replace({path:“/home”})<br> replace跟push很像，但不会向 history 添加新记录，而是替换当前的history记录</p> 
<p>2.this.$router.go(1)在浏览器记录中前进一步，等同于 history.forward()<br> this.$router.go(-1)后退一步记录，等同于 history.back()</p> 
<h2><a id="hashhistory_193"></a>路由模式–hash&amp;history</h2> 
<p><strong>hash模式：</strong> 在浏览器中符号“#”，#以及#后面的字符称之为hash，用window.location.hash读取；<br> 特点：hash虽然在URL中，但不被包括在HTTP请求中；用来指导浏览器动作，对服务端安全无用，hash不会重加载页面。<br> hash 模式下，仅 hash 符号之前的内容会被包含在请求中，如 <a href="https://www.xxx.com/" target="_blank" rel="noreferrer noopener">http://www.xxx.com</a>，因此对于后端来说，即使没有做到对路由的全覆盖，也不会返回 404 错误。</p> 
<p><strong>history模式：</strong> history采用HTML5的新特性；且提供了两个新方法：pushState（），replaceState（）可以对浏览器历史记录栈进行修改，以及popState事件的监听到状态变更。<br> history 模式下，前端的 URL 必须和实际向后端发起请求的 URL 一致，如 <a href="https://www.xxx.com/items/id" target="_blank" rel="noreferrer noopener">http://www.xxx.com/items/id</a>。后端如果缺少对 /items/id 的路由处理，将返回 404 错误。<strong>Vue-Router 官网里如此描述：</strong>“不过这种模式要玩好，还需要后台配置支持……所以呢，你要在服务端增加一个覆盖所有情况的候选资源：如果 URL 匹配不到任何静态资源，则应该返回同一个 index.html 页面，这个页面就是你 app 依赖的页面。</p> 
<p><strong>abstract 路由模式</strong><br> abstract 是vue路由中的第三种模式，本身是用来在不支持浏览器API的环境中，充当fallback，而不论是hash还是history模式都会对浏览器上的url产生作用，本文要实现的功能就是在已存在的路由页面中内嵌其他的路由页面，而保持在浏览器当中依旧显示当前页面的路由path，这就利用到了abstract这种与浏览器分离的路由模式。</p>
